# 部署模板与数据库升级

本目录移植自 `AIassist-local-20261102.zip`，供合并后的后端在目标服务器部署使用。复制这些文件不代表已执行部署；`server-version.json` 是原包所附的旧发布身份资料，不是本次合并版的运行证明。

## 模式和账号

- 本地后端使用 `BACKEND_MODE=local`。已登录的本地普通账号可以使用现有审查工作区。
- 服务器使用 `BACKEND_MODE=server`。常规项目、检测、完整性、导出与原文接口仅管理员可用；普通账号通过其本人的历史上报和服务器收件接口交换记录。
- 本地业务工作区仍共享，不会因为增加账号自动成为按用户隔离的项目库。
- 新注册账号始终为普通用户。部署后先注册目标账号，再在相同后端环境和数据库配置下执行 `python -m app.cli.manage_admin 用户名 --role admin`。变更角色会撤销该账号的旧会话，需要重新登录。
- 禁用账号会撤销其全部会话；命令行工具保护最后一个启用的管理员，注册接口不能自行授予管理员。

## 数据库

升级前备份实际 `DATABASE_URL` 指向的数据库和文件存储，停止审查写入后再执行发布。不要将示例环境文件覆盖到现有服务器配置；保留原数据库连接和模型配置。

后端启动保留原有任务中断恢复，并增量创建账号、会话、限流、历史上传/分发/导入表。原问题记忆表、版本基准关系和业务表均保留。

已有 MySQL 的相关报告 JSON、记忆快照和原始附件列会幂等扩展为 `LONGTEXT` / `LONGBLOB`，以避免旧 `TEXT` / `BLOB` 的 64 KiB 上限。迁移不重建表或删除行，但目标数据库账号需要相应 DDL 权限。SQLite 保持原类型。建议先在数据库副本上验证迁移、历史记录读取及导入，再更新实际服务。

本地数据目录的选择由启动脚本处理，升级时不能静默改用另一份空库。

## 模板使用

`initialize_server.py` 是需要在目标 Linux 服务器以 root 运行的初始化工具，会创建服务、配置和数据库。它不应在开发机、已有无关数据库或尚未审核配置的环境直接执行。先配置和构建目标镜像，检查服务名称、数据目录、网络地址与权限，再将初始化或更新作为单独部署操作执行。

`aiassist-api.service`、`aiassist-mysql.service`、`aiassist-mysql.cnf` 是模板。原压缩包中的内网地址、镜像名称及快照哈希只描述原部署，应按目标环境配置，不作为新合并版的已验证值。
