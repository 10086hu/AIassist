# 项目文档

## 一、开发内容

本项目拟建设一套面向可行性研究报告审查场景的智能化辅助系统，整体由规则库网站和九项检测桌面端应用两部分组成，并配套建设后端服务、数据存储、文档解析、规则管理、检测结果管理等支撑能力。系统面向项目申报、项目评审、内部初审和专家辅助审查等业务环节，重点解决可研报告内容多、审查口径复杂、人工比对耗时长、审查依据分散、结果留痕不足等问题。

项目开发内容包括规则库网站建设、桌面端检测应用建设、九项检测能力建设、后端服务建设、数据与知识资源建设、系统集成与安全支撑建设等内容。

### （一）规则库网站建设

规则库网站用于集中维护可研报告审查所需的规则、依据、标准、术语、价格参考、历史项目资料和审查模板，为桌面端九项检测提供统一的规则来源和数据支撑。网站面向系统管理员、业务审查人员和规则维护人员，提供规则录入、规则分类、规则检索、规则更新、版本留痕和启停管理等功能。

规则库网站主要建设内容如下：

1. 规则分类管理

   建立面向可研报告审查业务的规则分类体系，按审查事项、业务领域、适用范围、依据来源、规则状态等维度组织规则内容。规则类型包括建设依据类规则、重复建设判断规则、功能对应关系规则、数据填报合理性规则、资源申请合理性规则、安全建设规则、价格合理性规则、软硬件价格参考规则、信创合规规则等。

2. 规则内容维护

   支持规则新增、编辑、删除、查询、启用、停用和版本更新。每条规则应包含规则名称、规则类型、适用场景、审查说明、判断条件、风险等级、整改建议、依据文件、发布日期、生效状态等信息。对于需要结构化判断的规则，应支持维护关键字段、阈值范围、匹配关键词、例外条件和提示语。

3. 政策依据与知识资料管理

   支持上传和维护政策文件、标准规范、审查指南、政务术语词典、历史审查资料等知识资源。系统应支持对文档资料进行分类、标签化和检索，并为后续智能检索、依据引用和审查结果说明提供资料来源。

4. 价格参考数据管理

   建设软硬件产品价格参考数据管理能力，支持维护产品名称、品牌、型号、规格、价格、来源、采集时间、适用范围等字段。价格参考数据可用于桌面端进行价格合理性判断和软硬件产品价格参考展示。

5. 规则检索与调用服务

   网站除提供人工维护界面外，还应向后端检测服务提供规则查询和调用能力。桌面端发起检测任务后，后端服务根据检测类型调用对应规则、知识资料和价格参考数据，形成可追溯的审查结果。

6. 规则版本与审计留痕

   对规则新增、修改、启停、删除等操作进行记录，保留操作人、操作时间、变更内容和版本信息。检测结果应记录命中的规则版本，保证后续复核时能够追溯当时采用的审查依据。

### （二）九项检测桌面端应用建设

桌面端应用为审查人员的主要使用入口，部署在用户的视窗系统电脑上。用户通过桌面端完成账号登录、可研报告选择、检测项勾选、检测任务提交、任务进度查看、检测结果展示和结果导出等操作。桌面端应用通过接口连接服务器端后端服务，检测逻辑、数据存储和规则调用统一由服务器完成。

桌面端应用主要建设内容如下：

1. 用户登录与工作台

   建设登录、注册、退出和主工作台页面。用户进入系统后，可在工作台查看当前账号、选择报告文件、选择检测项目、发起检测任务，并查看任务状态和检测结果。

2. 报告文件选择与上传

   支持用户选择可研报告及相关附件，文件类型包括文字报告、表格清单、政策依据附件等。桌面端负责文件选择、基础校验和任务提交，后端负责文件接收、解析、结构化抽取和审查计算。

3. 检测项选择与任务创建

   提供九项检测能力的勾选入口，支持全选、清空和按需选择。用户可以根据项目审查需要选择一项或多项检测内容，系统根据用户选择创建对应检测任务。

4. 任务进度与结果展示

   桌面端应展示检测任务的创建状态、执行状态、完成状态和异常状态。检测完成后，按检测项展示问题清单、风险等级、判断依据、原因说明、整改建议和关联原文位置，便于审查人员快速定位问题。

5. 检测结果导出

   支持将检测结果导出为审查报告或问题清单，内容包括项目基本信息、检测范围、检测时间、检测结论、问题明细、依据说明和整改建议，方便归档和流转。

### （三）九项检测能力建设

系统围绕可研报告智能审查需求，建设以下九项检测能力：

1. 建设依据审查

   根据上传的政策依据、批复文件、规划文件和可研报告中的建设依据表述，检查依据内容是否完整、是否匹配建设内容、是否存在依据缺失、依据过期、依据与建设内容不一致等问题。

2. 重复建设检查

   对当前可研报告以及与本报告相关联的历史报告、分期报告、补充报告等材料中的功能点、建设内容和系统能力进行抽取与比对，重点检查本报告内部是否存在重复建设，以及本项目不同阶段报告之间是否存在重复建设、功能重复描述、相近功能重复申报等情况。例如，可对同一项目的一期报告和二期报告进行关联比对，识别二期建设内容中与一期已建设内容重复或边界不清的部分。

3. 建设功能的对应关系检查

   检查建设内容、业务功能分析、系统功能需求分析、应用功能设计和功能点清单之间是否存在对应关系，识别功能前后不一致、需求无设计、设计无依据、功能点遗漏等问题。

4. 数据填报合理性检查

   对用户量、业务量、并发数、高峰期用户、活跃用户比例、数据量、存储量、计算资源依据等内容进行合理性检查，识别数据填报缺失、口径不一致、数量级异常、前后矛盾等问题。

5. 资源申请的合理性检查

   检查云资源、基础软硬件资源、数据库、中间件、存储、计算、网络和安全资源申请是否与系统功能、数据规模、访问规模和性能需求相匹配，识别资源申请过高、过低、依据不足或配置不完整等情况。

6. 安全内容的合理性检查

   检查安全需求分析、安全建设内容、安全防护措施、等级保护要求、数据安全要求和项目建设内容之间是否匹配，识别安全内容缺失、措施不足、要求与建设内容不一致等问题。

7. 价格合理性检查

   依据软件造价、功能点拆分、工作量估算、产品报价、历史项目价格和规则库价格参考数据，对项目预算和报价进行合理性分析，识别价格明显偏高、价格依据不足、费用构成不清晰等问题。

8. 软硬件产品价格参考

   根据规则库网站维护的软硬件产品价格参考数据，对可研报告中的产品名称、品牌、型号、规格和价格进行匹配，向审查人员展示参考价格、来源信息和差异提示，为价格评审提供辅助依据。

9. 非信创内容检查

   检查可研报告中是否存在非信创技术、非国产化产品或不符合国产化替代要求的内容，识别产品选型不合规、技术路线不符合要求、描述中存在非信创关键词等问题，并给出替换或复核建议。

### （四）后端服务与数据支撑建设

后端服务部署在服务器端，作为规则库网站和桌面端应用的统一业务支撑。后端主要负责账号认证、项目管理、文件接收、文档解析、结构化字段抽取、规则调用、检测任务调度、检测结果存储、任务状态查询和结果导出等功能。

后端服务建设内容包括：

1. 项目管理能力

   支持项目创建、项目查询、项目状态维护和项目资料关联，保存项目名称、建设单位、说明、创建时间、检测状态等信息。

2. 文档解析能力

   支持对可研报告、表格清单和附件资料进行解析，提取项目基本信息、功能点、资源申请、价格清单、安全内容、依据文本和产品信息等审查所需字段。

3. 检测任务管理能力

   根据桌面端选择的检测项创建检测任务，支持任务排队、执行、状态更新、异常记录和结果回传。每个检测项可独立生成结果，便于分项查看和复核。

4. 规则调用与智能判断能力

   根据检测类型调用规则库、知识资料、价格参考数据和历史项目数据，结合文本相似度、规则匹配、结构化字段校验和模型辅助判断，生成检测结论、问题原因和整改建议。

5. 结果存储与追溯能力

   保存检测结果、命中规则、关联原文、风险等级、判断原因、建议措施、模型名称、执行时间和操作记录，确保检测过程可追溯、结果可复核。

### （五）数据资源建设

项目需要建设和维护以下数据资源：

1. 规则数据

   包括九项检测所需的审查规则、判断条件、阈值范围、风险等级、整改建议和适用场景。

2. 知识资料

   包括政策依据、标准规范、审查指南、历史审查意见、政务术语词典和常见问题库。

3. 项目数据

   包括项目基本信息、上传报告、附件资料、功能点清单、资源清单、价格清单和检测任务记录。

4. 结果数据

   包括检测结论、问题清单、风险等级、判断依据、建议内容、导出报告和审计日志。

5. 价格参考数据

   包括软硬件产品名称、品牌、型号、规格、参考价格、数据来源、采集时间和有效状态。

### （六）系统集成与安全建设

项目采用桌面端、规则库网站、后端服务和数据库协同的建设模式。桌面端负责用户交互，规则库网站负责规则和知识资料维护，后端服务负责统一业务处理，数据库负责数据持久化。

系统集成与安全建设内容包括：

1. 桌面端与后端接口集成

   实现登录认证、报告上传、任务创建、状态查询、结果获取和报告导出等接口对接。

2. 规则库网站与检测服务集成

   实现规则、知识资料、价格数据和检测任务之间的联动，保证检测服务能够使用最新有效规则。

3. 权限控制

   根据用户角色区分普通审查人员、规则维护人员和系统管理员权限，限制不同用户可访问的数据范围和功能范围。

4. 数据安全

   对报告原文、审查结果、规则数据和用户信息进行统一管理。正式环境中，后端服务和数据库应部署在受控服务器环境，敏感配置通过服务器环境变量或专用配置文件管理。

5. 操作审计

   对用户登录、规则变更、项目创建、任务执行、结果导出等关键操作进行日志记录，满足后续追溯、复核和安全管理要求。

## 二、交付目标和考核指标

本项目交付目标是形成一套可部署、可使用、可维护、可扩展的可研报告智能审查辅助系统，实现规则库网站与九项检测桌面端应用协同运行，为可研报告审查提供规则维护、资料管理、报告解析、检测任务创建、九项检测执行、结果展示、结果导出和审计留痕等能力。项目交付后，应能够支撑审查人员对可研报告开展标准化、结构化、可追溯的辅助审查，提升审查效率和审查一致性。

### （一）总体交付目标

1. 建成规则库网站

   完成规则库网站建设，支持审查规则、政策依据、知识资料、价格参考数据、术语词典和历史资料的统一维护。规则库网站应具备规则分类、规则录入、规则查询、规则编辑、规则启停、版本管理和操作留痕能力，为九项检测提供统一的数据和规则来源。

2. 建成九项检测桌面端应用

   完成面向审查人员使用的视窗桌面端应用，支持用户登录、报告选择、检测项选择、任务提交、任务状态查看、检测结果展示和结果导出。桌面端应提供九项检测入口，能够通过后端接口调用服务器端检测能力。

3. 建成后端服务与接口体系

   完成后端服务建设，提供用户认证、项目管理、文件上传、文档解析、检测任务管理、规则调用、检测结果查询和结果导出等接口。后端服务应支持规则库网站和桌面端应用共同调用，保证业务流程闭环。

4. 建成九项检测能力

   围绕建设依据审查、重复建设检查、建设功能对应关系检查、数据填报合理性检查、资源申请合理性检查、安全内容合理性检查、价格合理性检查、软硬件产品价格参考、非信创内容检查九项内容，形成可执行的检测流程和结果输出能力。

5. 建成数据存储与追溯体系

   完成项目数据、规则数据、知识资料、检测任务、检测结果、价格参考数据和操作日志的数据存储设计与落地，实现检测过程可记录、检测结果可查询、审查依据可追溯、操作行为可审计。

6. 完成部署、测试和文档交付

   完成系统部署配置、功能测试、接口测试、联调测试和验收测试，形成部署说明、操作手册、接口说明、数据库说明、测试报告和验收材料，满足后续运行维护和功能扩展需要。

### （二）主要交付物

项目交付物包括软件系统、数据资源、技术文档、测试材料和部署成果五类。

1. 软件系统交付物

   交付规则库网站一套，包含规则管理、知识资料管理、价格参考数据管理、用户权限管理和操作审计等功能。

   交付九项检测桌面端应用一套，包含登录、报告选择、检测项勾选、任务提交、结果展示和结果导出等功能。

   交付后端服务一套，包含项目管理、文件上传、文档解析、检测任务管理、检测结果管理、规则调用和系统健康检查等接口。

   交付数据库结构和初始化脚本，包含用户、项目、规则、知识资料、价格参考、检测任务、检测结果和审计日志等数据表。

2. 数据资源交付物

   交付九项检测所需的基础规则数据。

   交付政策依据、审查标准、术语词典等知识资料的初始化数据。

   交付软硬件产品价格参考数据的维护模板和样例数据。

   交付可研报告、功能点清单等测试样例数据。

3. 技术文档交付物

   交付项目总体说明文档。

   交付系统部署说明文档。

   交付用户操作手册。

   交付接口说明文档。

   交付数据库设计说明文档。

   交付规则库维护说明文档。

   交付测试报告和验收说明。

4. 测试与验收交付物

   交付功能测试用例和测试结果。

   交付九项检测样例测试结果。

   交付桌面端与后端接口联调记录。

   交付规则库网站与检测服务联调记录。

   交付问题修复记录和最终验收清单。

5. 部署运行交付物

   交付服务器端部署环境。

   交付后端服务运行配置。

   交付数据库初始化结果。

   交付桌面端安装包或可执行程序。

   交付运行账号、角色权限和基础配置说明。

### （三）功能考核指标

1. 规则库网站功能指标

   规则库网站应支持规则新增、编辑、删除、查询、启用、停用和版本管理。

   规则库网站应支持按规则类型、适用范围、规则状态、关键词等条件进行检索。

   规则库网站应支持政策依据、标准规范、术语词典、价格参考数据等资料维护。

   规则库网站应记录规则变更日志，能够查询规则修改人、修改时间和修改内容。

   规则库网站维护的有效规则应能够被后端检测服务调用。

2. 桌面端应用功能指标

   桌面端应支持用户登录、退出和主工作台展示。

   桌面端应支持选择可研报告及相关附件，并对文件格式进行基础校验。

   桌面端应完整展示九项检测内容，支持单项选择、多项选择、全选和清空。

   桌面端应能够向后端提交检测任务，并展示任务创建、执行、完成和异常状态。

   桌面端应能够展示检测结果明细，包括检测项、问题描述、风险等级、判断依据、原因说明和整改建议。

   桌面端应支持检测结果导出，导出内容应满足审查归档和流转需要。

3. 九项检测功能指标

   系统应覆盖九项检测入口，九项检测均能够形成独立检测结果。

   建设依据审查应能够识别依据缺失、依据不匹配、依据描述不完整等问题。

   重复建设检查应能够对本报告内部功能点、建设内容进行相似度比对，也应能够对本报告与关联报告之间的建设内容进行跨报告比对，并输出疑似重复项、重复来源、相似原因和复核建议。

   建设功能对应关系检查应能够识别建设内容、需求分析、功能设计和功能点清单之间的不一致问题。

   数据填报合理性检查应能够识别关键数据缺失、数量级异常、前后口径不一致等问题。

   资源申请合理性检查应能够识别资源配置与业务规模、功能需求、性能需求不匹配等问题。

   安全内容合理性检查应能够识别安全内容缺失、安全措施不足、等级保护要求不匹配等问题。

   价格合理性检查应能够结合规则或价格参考数据输出价格异常提示。

   软硬件产品价格参考应能够展示产品参考价格、来源信息和差异提示。

   非信创内容检查应能够识别报告中的非信创产品、技术或疑似不合规描述。

4. 后端服务功能指标

   后端服务应提供项目创建、项目查询、文件上传、检测任务创建、任务状态查询、结果查询等接口。

   后端服务应支持常见可研报告材料格式的接收和解析，包括文字报告、表格清单和相关附件。

   后端服务应能够保存检测任务和检测结果，并支持按项目、检测项、风险等级等维度查询。

   后端服务应支持规则库有效规则、知识资料和价格参考数据的调用。

   后端服务应具备异常处理和错误提示能力，接口返回信息应清晰、可定位。

### （四）性能与稳定性考核指标

1. 响应性能

   规则库网站常规查询、新增、编辑、启停等操作应在正常网络环境下保持较好的响应速度。

   桌面端常规页面切换、检测项选择、任务提交等操作应流畅，无明显卡顿。

   后端接口在常规并发访问下应保持稳定，健康检查接口应能够快速返回服务状态。

2. 检测任务性能

   系统应支持单个项目同时选择多项检测并创建检测任务。

   对中等规模可研报告进行检测时，系统应能够完成文档解析、规则匹配、模型判断和结果生成，任务状态应可查询。

   对耗时较长的检测任务，应提供任务状态更新，避免用户界面长时间无反馈。

3. 稳定性

   系统应支持连续运行和多次任务提交，不能因单个文件解析失败或单项检测异常导致整体服务不可用。

   后端服务应对上传空文件、不支持格式、参数缺失、规则缺失等异常情况进行处理，并返回明确提示。

   桌面端应对未选择文件、未选择检测项、网络连接异常、服务端异常等情况进行友好提示。

### （五）数据与安全考核指标

1. 数据完整性

   项目基本信息、上传文件记录、检测任务、检测结果、命中规则和操作日志应能够完整保存。

   检测结果应包含检测项、结果标签、风险等级、问题原因、整改建议和依据来源等必要字段。

   规则变更后应保留版本或日志记录，检测结果应能够追溯对应规则来源。

2. 权限控制

   系统应按角色区分普通审查人员、规则维护人员和系统管理员。

   普通审查人员应主要使用检测任务和结果查看功能。

   规则维护人员应能够维护规则、知识资料和价格参考数据。

   系统管理员应能够进行用户、角色、系统配置和审计日志管理。

3. 安全要求

   账号密码、数据库连接、模型密钥等敏感信息不得硬编码在客户端或公开代码中。

   服务器端应统一保存报告文件、检测结果和规则数据，避免关键业务数据分散在用户本机。

   系统应记录关键操作日志，包括登录、规则变更、文件上传、任务创建、结果导出等行为。

### （六）文档与验收考核指标

1. 文档完整性

   项目交付时应提供部署说明、操作手册、接口说明、数据库说明、规则维护说明和测试报告。

   文档内容应与实际交付系统一致，能够指导部署人员完成安装配置，指导业务人员完成基本操作。

2. 测试完整性

   应完成规则库网站、桌面端应用、后端服务和九项检测能力的功能测试。

   应完成桌面端与后端服务的接口联调测试。

   应完成规则库网站与检测服务的规则调用测试。

   应使用样例报告或样例清单完成九项检测结果验证。

3. 验收标准

   系统功能应覆盖本项目约定的主要开发内容。

   交付物应完整、可运行、可部署、可演示。

   九项检测应能够完成任务创建并输出结构化结果。

   规则库网站应能够维护规则并支撑检测服务调用。

   桌面端应能够完成从报告选择、检测项选择、任务提交到结果查看的完整流程。

   验收测试中发现的问题应完成修复或形成经确认的遗留问题清单。

## 三、技术路线

本项目采用“桌面端应用 + 后端服务 + 规则库网站 + 数据库 + DeepSeek 辅助分析”的技术路线。桌面端负责报告选择、检测项选择、任务提交和结果展示；后端服务负责文件解析、规则匹配、数据比对、模型调用和结果生成；规则库网站负责规则、知识资料和价格参考数据维护；数据库负责项目、报告、任务、规则和检测结果存储。

DeepSeek 接口只在第 2 项重复建设检查和第 5 项资源申请合理性检查中作为辅助能力使用，主要用于文本理解、语义判断、原因说明和建议生成。第 8 项软硬件产品价格参考不依赖大模型，采用产品信息抽取、规则匹配和价格库比对方式实现。

### （一）第 2 项：重复建设检查技术路线

重复建设检查分为两类：一是本报告内部重复检查，二是本报告与关联报告之间的重复检查。关联报告包括同一项目的一期报告、二期报告、续建报告、补充报告和历史版本报告等。

实现路线如下：

1. 报告关联

   在项目管理中记录报告所属项目、建设阶段、报告类型和关联关系。用户上传报告时，可选择关联的一期报告、历史报告或已批复报告，作为重复建设比对范围。

2. 内容抽取

   后端解析当前报告和关联报告，抽取功能点、建设内容、系统模块、业务能力、建设目标、服务对象和来源章节。表格内容优先用结构化解析，正文内容可调用 DeepSeek 辅助抽取为固定字段。

3. 文本标准化

   对抽取出的建设内容进行清洗和归一化处理，包括去除无效字符、统一术语、合并相近表达、记录来源章节和生成摘要。

4. 相似度比对

   本报告内部进行功能点两两比对；本报告与关联报告之间进行跨报告比对。后端先用关键词重合、文本相似度、语义相似度等方法筛选疑似重复项，减少模型调用次数。

5. DeepSeek 复核

   对疑似重复项调用 DeepSeek 进行语义复核，判断其属于完全重复、部分重复、阶段延续、相似但不重复或需人工确认。模型输入只包含必要片段、来源信息和项目阶段信息。

6. 结果输出

   输出疑似重复内容、重复来源、所属报告、来源章节、相似度、判断原因、风险等级和整改建议。桌面端按“本报告内部重复”和“关联报告重复”分类展示，便于审查人员复核。

### （二）第 5 项：资源申请的合理性检查技术路线

资源申请合理性检查用于判断服务器、云资源、数据库、中间件、存储、网络、安全设备和基础软件等资源申请是否与建设内容、业务规模、数据量、并发量和性能需求匹配。

实现路线如下：

1. 资源清单抽取

   后端从可研报告、资源清单、预算表和附件中抽取资源类型、规格、数量、单位、用途、申请依据、关联业务模块和预算金额。表格优先使用结构化解析，正文说明可调用 DeepSeek 辅助抽取。

2. 业务指标抽取

   同步抽取用户数量、并发用户数、业务量、数据量、存储周期、峰值访问量、响应时间和安全等级等指标，作为资源合理性判断依据。

3. 规则库校验

   在规则库中维护资源申请规则，如并发量与服务器配置关系、数据量与存储容量关系、数据库高可用要求、安全等级与安全资源要求等。后端根据规则对资源申请进行校验。

4. 合理性判断

   对可量化内容使用规则和公式判断，如数量是否异常、配置是否不足、存储是否明显偏高。对说明性内容使用 DeepSeek 判断申请理由是否充分、资源用途是否清楚、是否与建设内容匹配。

5. 结果输出

   按计算资源、存储资源、数据库资源、中间件资源、网络资源和安全资源分类输出问题。每条结果包含资源名称、申请配置、判断结论、问题原因、命中规则和整改建议。

### （三）第 8 项：软硬件产品价格参考技术路线

软硬件产品价格参考功能不使用 DeepSeek 接口，采用价格参考库和规则匹配方式实现。该功能主要为审查人员提供价格参考，不直接替代最终价格审定。

实现路线如下：

1. 价格参考库建设

   在规则库网站维护产品价格数据，包括产品名称、标准名称、品牌、型号、规格、类别、参考单价、价格来源、采集日期和有效状态。价格来源可包括人工维护数据、历史项目价格、询价记录和公开采购信息。

2. 产品信息抽取

   后端从可研报告、预算表、设备清单和软件清单中抽取产品名称、品牌、型号、规格、数量、单位、单价、总价和用途。表格数据通过字段映射解析，正文中的产品描述通过关键词和规则提取。

3. 产品匹配

   按“标准名称匹配、品牌型号匹配、规格参数匹配、关键词匹配”的顺序查找参考价格。匹配不到时，标记为“未找到参考价格”，提示补充产品名称、品牌、型号或规格。

4. 价格差异计算

   后端将申报价格与参考价格进行比较，计算差异金额和差异比例。规则库中维护偏差阈值，如正常、偏高、明显偏高、需人工复核等。

5. 结果输出

   桌面端展示申报产品、申报价格、匹配到的参考产品、参考价格、价格来源、采集日期、差异比例和复核建议。结果可导出到审查报告或问题清单中。

### （四）实现保障

1. 后端统一调用

   DeepSeek 接口只由后端服务调用，接口密钥保存在服务器环境变量或配置文件中，不写入桌面端和代码仓库。

2. 结构化输出

   DeepSeek 返回结果必须使用固定字段，后端完成格式校验后再入库，避免模型自由文本直接进入最终结果。

3. 规则优先

   能通过规则、公式、表格解析和数据库匹配解决的问题，优先使用确定性方法实现。DeepSeek 只用于文本语义理解和复杂说明判断。

4. 可追溯

   每条检测结果保存来源报告、来源章节、命中规则、模型名称、判断原因和生成时间，支持人工复核和后续追溯。

## 四、计划进度

项目计划按“优先实现高确定性功能、再推进剩余功能方案确认”的方式开展。当前优先从第 1、2、3、4、8、9 项功能中选择四项在本周内完成，其余两项在下周完成。第 5、6、7 项涉及资源合理性、安全合理性和价格合理性，规则口径和实现细节需要与公司进一步确认，因此安排在后续阶段推进。

### （一）第一周：完成六项中的四项功能

本周内从以下六项功能中优先完成四项：

1. 建设依据审查
2. 重复建设检查
3. 建设功能的对应关系检查
4. 数据填报合理性检查
8. 软硬件产品价格参考
9. 非信创内容检查

本周重点完成所选四项功能的基础流程，包括报告解析、字段抽取、规则匹配、检测结果生成、桌面端结果展示和基础测试。对于重复建设检查，应优先实现本报告内部比对和关联报告比对的基础能力。对于软硬件产品价格参考，应优先实现价格参考库匹配和价格差异提示，不接入大模型。

### （二）第二周：完成六项中的剩余两项功能

下周完成第 1、2、3、4、8、9 项中尚未完成的两项功能，补齐六项功能的完整检测入口和结果输出能力。

本阶段重点包括：

1. 完成剩余两项功能的后端检测逻辑。
2. 完成对应规则、字段和结果格式整理。
3. 完成桌面端检测项调用和结果展示。
4. 对六项功能进行整体联调，保证能够从报告上传、任务创建到结果查看形成闭环。

### （三）第三周：与公司商议确认剩余三项实现方式

第三周重点与公司沟通确认第 5、6、7 项功能的业务规则、判断口径和实现边界，包括：

5. 资源申请的合理性检查
6. 安全内容的合理性检查
7. 价格合理性检查

本阶段主要工作包括：

1. 梳理三项功能所需的数据字段、规则依据和样例材料。
2. 明确哪些内容使用固定规则判断，哪些内容需要 DeepSeek 辅助分析。
3. 确定结果展示字段、风险等级和整改建议口径。
4. 形成三项功能的细化实现方案和开发清单。

### （四）第四周：启动剩余三项功能实现

第四周开始实现第 5、6、7 项功能。优先完成规则明确、数据结构清晰的部分，再逐步补充模型辅助判断和复杂规则。

本阶段重点包括：

1. 建设第 5、6、7 项功能所需的规则表、字段表和结果表结构。
2. 实现资源申请、安全内容、价格合理性相关字段抽取。
3. 实现规则校验、问题生成和结果展示。
4. 根据公司确认结果接入 DeepSeek 辅助判断能力。
5. 完成三项功能的初步测试和问题修正。

### （五）阶段性成果

按照以上计划推进后，前两周完成第 1、2、3、4、8、9 项六项功能的基础可用版本；第三周完成第 5、6、7 项实现方式确认；第四周开始第 5、6、7 项开发，实现后九项检测能力逐步形成完整闭环。
