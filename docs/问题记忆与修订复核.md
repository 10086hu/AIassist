# 问题记忆与修订复核

> 本文记录初版问题记忆的实现与当时的验证结果。2026-11-15 的项目背景、人工反馈、证据对照、持续整理和第 3 版传输能力，见 [同项目问题记忆升级说明](同项目问题记忆升级说明_20261115.md)。当前配置与回归结果以新说明及对应验证记录为准。

本次在公共结果处理层增加跨版本问题跟踪，不修改 `backend/app/modules/` 下各模块的判定规则、阈值、检测条件和原文定位规则。仍执行用户选择的完整规则检查，随后区分旧问题和新问题；适用公共 AI 整理队列的模块优先整理旧问题。

## 桌面端使用方式

检测选项中新增“问题记忆基准”：

- **自动关联同名报告最近检测**：默认选项。限同一项目、同名报告，分模块寻找最近一次检测，沿已有版本链追溯。文件名中的年份、期次、修订后缀不会自动剥除，避免错认其他报告。
- **选择某次历史检测**：报告改名后，手动选择它对应的上一版。此后同名新版本自动继续这条版本链。
- **作为新报告，不关联历史**：创建独立问题记录。该选择仅作用于本次检测，下一次恢复自动关联。

每个模块的审查记录中新增“修订进展与问题跟踪”，展示上次未解决数、本次确认解决数、仍存在、内容变化、再次出现、本次首次发现和待确认数。已解决和待确认的问题可以展开，并打开当时的历史记录；不会拿旧版位置跳转当前原文。

每条当前问题保留唯一跟踪编号、出现次数、匹配方式和上一版意见。超过原有主列表展示上限的问题仍全部保存、参与跟踪，并可在补充问题区展开。导出的 HTML 审查报告包含完整问题和跟踪汇总。

## 匹配与解决依据

匹配先使用规范化指纹，再使用受规则、对象和证据限制的文本相似度；实行一对一匹配，对近似候选无法可靠区分时不强行合并。相似度匹配不需要新增大模型服务、训练双塔模型或部署向量数据库。

同一问题再次发现时标记“仍然存在”；可靠匹配但内容改变时标记“内容有变化”；已解决的问题重新出现时标记“再次出现”。未可靠匹配的新问题保留并展示，不能为了数量下降而隐藏真实风险。

“未再次检出”本身不能作为已解决依据。确认解决要求检测范围与规则定义一致、正文可读、检测完整，并且原问题所属规则明确通过且没有同规则当前问题；敏感词问题也可通过重新检测后正文中已不存在原命中词确认消除。规则变化、范围变化、解析限制、失败、中断或证据不足时保留“待确认”。每条历史问题保留其原检测范围，避免经过数次范围变化后被误判为解决。

如果文件与该问题最后一次检出时完全相同，不会仅因复检结论变化标记“已解决”。如果文件确实已经修改、上次修改版检测失败，再次检测成功则仍可确认真正的修复。

重复建设的独立提取、候选检索和模型裁定流程保留原逻辑；没有明确反向验证证据的历史重复项保留待确认，不将“这次没有召回”当作已解决。安全模块保留其独立复核流程，采用该模块明确的非跳过通过结果作为解决依据。

## AI 排队与时间预算

公共 AI 整理队列优先处理：未解决的历史问题、历史问题再次出现、首次发现问题。同类历史问题中，优先尚未成功复核或本次内容变化的项，其后按最久未复核排序，避免每次都耗时在固定前几条。

保留现有每模块 60 秒、单项最多 15 秒、每次最多 5 项的预算。逐条区分已复核、失败和额度内未处理；没有轮到的项保留规则意见，并在后续修订中继续参与排队。测试中的 API 调用使用模拟响应，未调用用户实际 API 或消耗用户额度。

## 存储与兼容

- 新增 `review_run_links` 保存每次检测的基准和报告版本链。
- 新增 `review_memory_revisions` 保存每条模块检测结果的问题快照。
- 不更改原有表字段；后端启动时按现有 `create_all` 机制创建新表。历史结果可以作为初始基准，其缺少的规则范围信息不会被伪造补齐。
- 每次检测独立保存快照，分支检测互不覆盖。记忆处理失败时保留规则结果及源文件，明确提示跟踪未完成，不标记历史问题已解决。
