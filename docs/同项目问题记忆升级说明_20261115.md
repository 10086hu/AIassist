# 同项目问题记忆升级说明（2026-11-15）

本次升级限定同一项目。既有模块仍按原规则完整检测，记忆层负责关联版本、保存对照证据、记录人工意见和安排辅助整理，不替换检测条件、阈值、价格标准或定位规则。

## 使用方法

1. 更新并重启后端和桌面端，进入原来的项目。在项目操作区点击“项目背景”，可填写项目类型、建设阶段、已有系统等事实和来源，也可为同一系统补充术语别名。无需填写也能照常检测。
2. 上传修改后的报告，正常选择检测模块。“问题记忆基准”默认关联同名报告最近版本；文件改名后手动选择对应上一版。不同年份、期次和修订后缀不会被自动忽略，避免错连版本。
3. 在审查记录查看“修订进展与问题跟踪”和整改对照，区分仍存在、内容变化、确认解决、再次出现、新增和待确认；可以比较上一版与本次的证据。
4. 展开“逐项核验与人工反馈”，记录疑似误报、已整改、不适用或需要再次核实，并填写说明。“已整改”还需填写修改位置或佐证。人工意见单独保存，仍需复检验证；可以撤销，保留审计历史。
5. 点击“继续整理历史问题”分批处理尚未整理的问题。使用模型需要主动勾选；未勾选时仅整理已有规则意见，不会标记成 AI 复核。失败项可明确重试或跳过，关闭应用后可继续已保存任务。已完成后可以显式新建一轮整理，原任务保留。
6. 通过原有导出入口保存 HTML 审查报告，其中包含修订对照、项目背景、人工意见和辅助整理结果。历史记录传输会携带问题记忆、项目背景和人工反馈；执行中的本机整理任务不随包迁移。

## 技术实现

- **结构化长期记忆**：每个项目独立保存背景事实、来源和术语别名；每次检测形成独立问题快照，反馈使用追加事件保存，保留记录人、时间、说明、佐证和撤销关系。
- **保守的问题关联**：先匹配稳定指纹，再在相同规则、相同对照类型内做有数量上限的词项检索和文本相似度匹配，支持人工维护的术语别名。数量、单位、否定、阶段和对象冲突会阻止近似合并，候选歧义时保留待核实。
- **证据支持的整改对照**：按需读取当前文档，保存原文摘录及段落、行或表格行引用。检索得到的片段仅作为核验参考；证据不足、文件不可完整读取或规则未完成时，不自动确认解决。旧版引用和本版引用分别保存。
- **可继续的辅助整理**：原检测中的公共 AI 整理仍保留原有时间预算，优先历史问题，并为新出现的高风险问题预留机会。新增整理任务按条持久化进度，每批最多五项；使用独占租约防止重复执行，中断后可显式恢复。真正完成的模型复核会参与后续版本的排队轮转，内容变化则重新优先；规则意见整理、失败和跳过不计作已完成模型复核。模型失败不覆盖规则结论。
- **受约束的上下文**：仅将本项目的有限背景和相关人工意见作为参考传给辅助模型，控制条数和长度；不把其中的文字当作规则指令，也不把历史意见当作本次原文证据。
- **传输兼容**：有项目背景或人工反馈时使用第 3 版记录包；没有这两类数据时继续使用原来的第 1/2 版形式。导入重新映射项目、结果、问题、反馈及撤销引用，禁止静默降级丢失记忆；旧版本包继续可导入。

本次没有训练双塔模型，没有引入向量数据库，也没有让系统自行改写规则或自动豁免历史误报。新风险仍正常显示；报告修改后问题数是否下降，取决于实际整改和复检证据。

## 验证范围

验证使用隔离数据库和模拟模型响应，不修改正式审查记录、不调用真实付费 API。原四份报告用于记忆层回放：读取原文，对此前保存的建设依据、敏感词、资源申请结果进行两次同文件上传验证，共 12 组，确认问题编号稳定、原规则判定保留、同文件不误销号。该验证不等于重新执行四份文档所有模块。

完整回归结果和规则文件逐项校验保存在 `.codex-run/memory-upgrade-20261115/`。原有规则模块文件以升级前后 SHA-256 比对确认未修改。

最终结果：后端 642 项通过，2 项因本地维护案例材料目录缺失而跳过；桌面客户端 31 项、WPF 联动 14 项全部通过，主程序构建 0 警告、0 错误。57 个既有规则文件逐项校验一致，也未新增规则文件。第 1/2 版传输包的规范化字节与升级前完全一致。回归中遇到的既有限流测试跨时间窗口波动，通过固定该测试的时钟消除，认证业务代码没有调整。

## 口头汇报参考

系统现在能记住同一项目历次审查发现的问题，报告修改后可连续跟踪整改情况，并对照前后证据。人工纠错和项目背景可以持续保存，未完成的辅助复核可以分批接着做。原有规则和判定标准保持不变，新出现的问题仍会正常检查。
