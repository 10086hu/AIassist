# 长报告重复建设检查

默认对当前报告内部及当前报告与历史报告采用同一套流程。接口和 WPF 结果结构保持兼容。

1. 按 Word 正文顺序解析章节和表格，保留标题层级、原文位置及合并单元格。表格不会再被统一附在文档末尾。
2. 从系统/模块/子功能清单直接生成模块摘要。同一系统内同一模块的子功能合并，设计与预算中的复述合并；不同系统或业务场景的同名模块分别保留。补充表格未覆盖的建设模块标题。
3. 摘要保留核心子功能、业务场景、建设范围，以及复用/升级/既有建设等原文说明。没有可用结构时，只对建设相关章节进行模型抽取，按约 6000 字分块并保留父级标题；输出截断时继续拆分，失败不能当作无重复。
4. 预计算关键词向量和倒排索引，默认每个模块检索前 5 个候选。同名、强匹配保留；核心子功能重叠可以补充整体文本相似度较低的候选。取消原有前 120 条功能点截断，报告后部模块会参与检查。
5. 每批最多 6 对候选，结合双侧原文进行模型复核。对不同业务场景的配置、合理升级、共性能力复用、父子模块和同一建设项复述进行区分。返回结果必须覆盖所有候选 ID；缺失或格式错误时缩小批次重试，不能静默丢掉候选。阳性仍需双侧可核验原文依据，证据定位到对应子功能所在位置。
6. 在服务器本地缓存文档模块及位置，30 天内复用；文件内容、模型、服务地址、处理版本变化会使缓存失效。同一历史文档换项目、期次或文件名仍可复用摘要，原文定位自动绑定本次文件名。失败的抽取不会写入缓存；模型复核结果每次重新产生。

检索使用现有关键词哈希向量和同义词规则，不需要额外模型服务或新依赖。相似度是筛选分数，不是重复建设概率。快速检索仍可能漏掉表述差异很大的重叠项，不能把未命中理解为确认不存在重复。

## 配置

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `DUPLICATE_CANDIDATE_TOP_K` | 5 | 每个模块进入复核的候选数量；同名和强匹配不受此数限制 |
| `DUPLICATE_JUDGE_BATCH_SIZE` | 6 | 每次模型请求最多比较多少对候选 |
| `DUPLICATE_JUDGE_BATCH_CHARS` | 24000 | 单批候选的输入字符预算；单个大模块可能单独复核 |
| `DUPLICATE_CACHE_ENABLED` | true | 是否复用文档模块摘要 |
| `DUPLICATE_CACHE_DIR` | 数据目录下的 `duplicate_cache` | 服务器本地缓存位置，需与数据库一样由服务器保护 |

若要更充分筛查，可把候选数量提高至 8～10；模型请求次数会相应增加。模型调用继续使用现有并发、单次超时及任务总时限设置。

## 验证方法

从仓库根目录运行（不会写入项目业务数据库）：

```powershell
backend\.venv\Scripts\python.exe scripts\benchmark_duplicate_long_report.py "报告.docx"
backend\.venv\Scripts\python.exe scripts\benchmark_duplicate_long_report.py "报告.docx" --with-model --output .cache\duplicate-benchmark.json
backend\.venv\Scripts\python.exe scripts\benchmark_duplicate_long_report.py "本期.docx" --history "往期.docx" --with-model
```

模型测速读取已有用户环境配置，不输出密钥。实际耗时受模型服务、候选数量和截断重试影响，不能用纯解析耗时代替完整复核耗时。

自动检查覆盖长文背景过滤、合并单元格、业务场景区分、建设/预算复述合并、未入表模块补充、120 条之后的模块、局部子功能重叠、缓存失效、批量结果完整性及原文定位。另用真实模型检查独立重复登录建设与不同业务复用表单引擎两类案例。

2026-10-12 最终版本实测：用户提供的 Word 报告（文档属性记录 135 页）解析 0.255 秒，整理为 42 个模块耗时 0.007 秒，筛选 28 对内部候选耗时 0.042 秒；从文档输入到真实模型内部复核及结果存储，共 30.737 秒，5 次模型请求。本次未产生内部重复建设问题，不能据此证明报告不存在重复。测试使用隔离的内存数据库，未改动项目业务记录。

两份各含 160 个分页符、约 16 万字符的人工长报告样例，内部及跨报告完整检查共 32.212 秒，检出了预设的内部重复与两项跨期重复。不同业务场景复用表单引擎的模型案例返回不重复。后端测试结果：260 通过、2 跳过。耗时为本次模型服务的观测值，不是固定时限保证。

## 跨报告补充优化

跨报告检查的内部候选与历史候选共用一条并发复核队列，避免先等待全部内部复核完成再启动历史复核。阶段和已用时间通过 `POST /api/evaluate/duplicate/compare/tasks` 创建任务、`GET /api/evaluate/tasks/{task_id}` 查询，WPF 客户端已接入。原同步接口继续兼容现有调用。

补充普通自定义样式中的中文章号、多级数字编号及 Word 大纲级别识别。对于“数据中台-任务管理-任务功能”这类扁平标题，前两层作为模块，后层保留为子功能，避免每个操作各自形成候选。上海海关样例约 37 万字符，原先会进入 64 块全文模型抽取；现在约 1.1 秒即可在本地生成 142 个模块摘要，无需模型逐块抽取。

丰富版当前/历史样例（6 个当前模块、3 个历史模块）真实模型检查 18.79 秒，2 次请求，检出 2 条内部重复及 5 条跨报告重复。该样例较小，其耗时不能代替实际长报告之间的完整对比耗时。

编译后的新客户端位于 `desktop-wpf/bin/duplicate-speed-preview/AiReportDesktop.exe`。旧的已启动客户端不会自动切换请求流程，需关闭并重新打开新客户端；服务也需重新加载代码。

本轮后端回归：265 项通过、2 项跳过；新客户端编译成功，0 警告、0 错误。实际运行后端已确认包含跨报告后台任务接口。
